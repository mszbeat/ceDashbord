# ممیزی تطبیق عددی قدیم / جدید

این سند وضعیت **واقعی** ابزارهای تطبیق در checkout فعلی را مستند میکند. هدف،
جلوگیری از ارجاع به اسکریپت/فایلی است که در ریپو وجود ندارد.

## چه چیزی در این ریپو هست

- موتور تحلیل عددی همان `newStats` / `bump` / `quantile` / `histogram` قدیمی،
  در `backend/services/evaluator/legacy/src/`.
- رجیستری سه بانک در `backend/services/evaluator/legacy/src/banks/*.js`.
- تستهای واحد، قرارداد روتر، رفتار کنترلرها، لایهٔ auth/refresh و حذف کد ملی
  در `backend/tests/*.test.js`.
- بررسی ساختار HTML زنده و مسیرهای auth در `backend/scripts/verify-pd2.js`
  (بخش دیتابیس فقط در صورت نصب `@electric-sql/pglite` اجرا میشود).
- تست سیاست رفرش توکن در `frontend/tests/refresh-policy.test.mjs`.

## چه چیزی در این ریپو نیست

- `report.html` قدیمی، پوشهٔ `reports/` و ابزارهای `report` / `ce-dashboard`
  (فقط `README.legacy.md` بهعنوان سند تاریخی باقی است).
- `backend/scripts/ab-parity.js`، `backend/scripts/numeric-parity.js`،
  `backend/scripts/import-legacy-reports.js` و `npm run test:ab-parity` /
  `test:numeric-parity`.
- اسکریپت `asigne.samad.access.to.role.js` و `npm run samad:assign`.

بنابراین هیچ ادعایی مبنی بر اجرای تست A/B قدیمی در همین checkout وجود ندارد.
برای مقایسهٔ دقیق دو خط لوله باید همان اسنپشاپ ورودی در محیطی که ابزارهای قدیمی
را دارد استفاده شود.

## نکتهٔ مهم دربارهٔ اختلاف اعداد

اختلاف جزئی اعداد بین دو اجرای واقعی معمولاً از **ردیفهای ورودی** میآید، نه از
کد تحلیل: نسخهٔ زنده شاخصها را هنگام Ingestion محاسبه و ذخیره میکند و گزارش
فقط همان مقادیر ذخیرهشده را `bump` میکند. اگر ingestion در زمان دیگری از API
زنده اجرا شود، صفحهبندی API پایدار نباشد (PRD D-01)، یا ردیفها با نسخهٔ قدیمیتر
کد ذخیره شدهباشند، چند ردیف نزدیک مرز بازهها جابهجا میشود. برای قضاوت دقیق،
هر دو خروجی باید از **یک اسنپشاپ یکسان** ساخته شوند.

در این تغییرات، منطق و نمایش دادههای تحلیل دستکاری نشده است؛ فقط پوستهٔ بصری
شیشهای/مدرن، دارایی صفحهٔ لاگین و لایهٔ تمدید نشست اصلاح شدهاند.
