# نــمـا — راهنمای اجرای گزارش‌های اعتبارسنجی

**نسخهٔ ۲٫۱۸٫۰ | رسالت، ملت و پست‌بانک | اجرای آفلاین با Node.js**

این برنامه فایل‌های JSON گزارش‌های شما را می‌خواند و یک داشبورد HTML فارسی می‌سازد. آمار، نمودارها، فیلتر موفق/ناموفق و فهرست گزارش‌های منتخب در داشبورد قرار دارند. دادهٔ کامل گزارش‌های منتخب در فایل همراهِ جداگانه ذخیره می‌شود، نه داخل HTML.

> **تغییر مهم فرمان اجرا:** پارامتر `MIN_NULL` حذف شده است. آرگومان سوم از این نسخه فقط `MAX_ROWS`، یعنی سقف تعداد ردیف‌های فهرست‌هاست. آستانهٔ بررسی null در رتبه‌بندی، داخل برنامه برابر **۳** ثابت است.

## 1. پیش‌نیاز و چیدمان پیشنهادی

- **Node.js نسخهٔ ۱۸ یا بالاتر**؛ با `node --version` نسخه را بررسی کنید.
- اجرای برنامه نیاز به `npm install`، اینترنت یا کتابخانهٔ npm ندارد.
- یک مرورگر به‌روز برای بازکردن HTML؛ مشاهدهٔ جزئیات به پشتیبانی از `DecompressionStream` نیاز دارد.

چیدمان پیشنهادی:

```text
work/
├── ce-dashboard/
├── reports/
│   ├── 1405-07-01/
│   │   ├── success/
│   │   │   └── reports.json
│   │   └── fail/
│   │       └── reports.json
│   └── 1405-07-02/
│       └── success/
│           └── another.json
└── report.html                  بعد از اجرای برنامه ساخته می‌شود
```

بانک از `input.method` تشخیص داده می‌شود:

| بانک | مقدار متد |
|---|---|
| ملت | `tavan_mellat` |
| رسالت | `tavan_resalat` |
| پست‌بانک | `tavan_postbank` |

در ورودی چندبانکی، فقط بانک دارای بیشترین گزارش معتبر انتخاب می‌شود و متدهای کنارگذاشته‌شده اعلام می‌شوند. **برای خروجی جداگانه، داده‌های هر بانک را جدا کنید.** در پوشهٔ کاری هر بانک، نام پوشهٔ ورودی را `reports` بگذارید.

## 2. فرمان اجرای جدید

در پوشهٔ `work`، یعنی **کنار پوشهٔ `ce-dashboard`**، اجرا کنید:

```bash
node ce-dashboard ./reports ./report.html 100
```

`ce-dashboard` یک پوشهٔ دارای `index.js` است؛ اجرای `node ce-dashboard` معتبر است.

شکل کلی فرمان:

```text
node ce-dashboard [INPUT_DIR] [OUTPUT_HTML] [MAX_ROWS]
```

| آرگومان | پیش‌فرض | کاربرد |
|---|---|---|
| `INPUT_DIR` | `./reports` | پوشهٔ داده‌های ورودی |
| `OUTPUT_HTML` | `./report.html` | مسیر فایل HTML خروجی |
| `MAX_ROWS` | `100` | سقف گزارش های قابل مشاهده؛ عدد صحیح از ۱ تا ۱۰٬۰۰۰ |

مثال‌ها، همگی از پوشهٔ `work`:

```bash
# مسیرها و سقف پیش‌فرض
node ce-dashboard

# ورودی و خروجی مشخص، سقف پیش‌فرض ۱۰۰
node ce-dashboard ./reports ./report.html

# حداکثر ۵۰۰ ردیف برای فهرست‌ها
node ce-dashboard ./reports ./report.html 500

# راهنمای فرمان
node ce-dashboard --help
```

اگر داخل خود پوشهٔ `ce-dashboard` هستید و داده‌ها طبق چیدمان بالا کنار آن هستند:

```bash
node index.js ../reports ../report.html 100
```

**مسیرهای نسبی از پوشه‌ای تفسیر می‌شوند که فرمان را در آن اجرا کرده‌اید، نه از محل فایل برنامه.** برای مسیر دارای فاصله از کوتیشن استفاده کنید.

### سقف ردیف گزارشات چه چیزی را تغییر می‌دهد؟

`MAX_ROWS` تعداد ردیف‌های ذخیره/نمایش‌داده‌شده در فهرست‌های بررسی را محدود می‌کند، نه تعداد گزارش‌هایی که تحلیل می‌شوند. سقف برای فهرست‌ها و گروه‌های مختلف، از جمله وضعیت‌ها، جداگانه اعمال می‌شود؛ سقف کل فایل HTML نیست. افزایش آن می‌تواند حجم خروجی و فایل خصوصی را بیشتر کند.

- شمارش، درصد و آمار روی همهٔ گزارش‌های واجد شرایط محاسبه می‌شوند.
- فهرست‌های تأخیر و زمان اجرای بیش از ۴ ثانیه **پیش از اعمال سقف، نزولی مرتب می‌شوند**.
- ممکن است عنوان یک فهرست تعداد بیشتری از ردیف‌های قابل مشاهده نشان دهد؛ این رفتار طبیعیِ سقف ردیف است.

## 3. خروجی کجاست و جزئیات چگونه باز می‌شوند؟

پس از اجرا، نسخه و مسیر فایل اجرایی، تعداد فایل‌ها و گزارش‌ها، بانک انتخاب‌شده، خطاها و مسیر خروجی در ترمینال چاپ می‌شوند.

برای ذخیره و بازشدن جزئیات، دو شرط ضروری است:

1. نام پوشهٔ ورودی دقیقاً **`reports`** باشد.
2. HTML **در کنار همان پوشه** تولید شود، نه داخل آن یا جای دیگر.

```text
work/
├── report.html
└── reports/
    ├── ... داده‌های ورودی شما ...
    └── _ce-dashboard-private/
        └── details-<token>.js     فایل همراهِ خودکار همین خروجی
```

برنامه JSONهای اصلی شما را بازنویسی نمی‌کند. HTML خروجی با اجرای مجدد جایگزین می‌شود و فایل همراه تازه‌ای ساخته می‌شود. فایل‌های همراه قدیمی خودکار پاک نمی‌شوند؛ تا وقتی HTML قدیمی را نگه داشته‌اید، فایل همراه متناظر آن را نیز نگه دارید.

اگر فقط HTML را جابه‌جا کنید، آمار دیده می‌شود ولی جزئیات باز نمی‌شوند. HTML و فایل همراه متناظر در `reports/_ce-dashboard-private` را با همین نسبت مسیر جابه‌جا کنید. تغییر محل HTML بعد از تولید، جای تولید صحیحِ آن را نمی‌گیرد؛ اگر فایل همراه ساخته نشده، گزارش را با چیدمان درست دوباره بسازید.

- روی شناسه کلیک کنید: **شناسهٔ کامل کپی می‌شود**.
- روی بقیهٔ ردیف کلیک کنید: **جزئیات همان گزارش در زبانهٔ جدید باز می‌شود**.
- شناسه‌ها در جدول ۸ کاراکتری‌اند، اما جست‌وجو و کپی با مقدار کامل کار می‌کند.
- پست‌بانک فقط ستون و جست‌وجوی `requestId` دارد.

## 4. قواعد مهم تحلیل

### آستانهٔ ثابت رتبه‌بندی

شاخص «رتبه‌بندی فاقد داده» بر پایهٔ ده کلید اصلی تعریف‌شده محاسبه می‌شود. اگر حداقل **۳ کلید** غایب یا null باشند، شاخص فعال می‌شود؛ نبود خود دادهٔ رتبه‌بندی یا ساختار نامعتبر نیز مشمول است.

### احتمال نکول دقیقاً ۰٫۵

در **ملت و پست‌بانک**، جدول توزیع احتمال نکول ردیف مستقل **«دقیقاً ۰٫۵۰»** دارد:

- `0.5` فقط در همان ردیف شمرده می‌شود.
- بازهٔ قبل، `0.40 <= PD < 0.50` است.
- بازهٔ بعد، `0.50 < PD < 0.60` است.
- مقدار بر اساس دادهٔ خام و **قبل از گردکردن** مقایسه می‌شود؛ مثلاً `0.5000001` دقیقاً `0.5` نیست.
- مقدار ۰٫۵ از میانگین یا سایر آمار حذف نمی‌شود؛ فقط شمارش توزیع تفکیک شده است.
- در ملت، منبع `output.PD` و در پست‌بانک `output.pd_default` است.

در پست‌بانک، مقدار ۰٫۵ برای مدل `no_strategy` پیش‌فرض است؛ از عدد ۰٫۵ به‌تنهایی نام مدل استنباط نمی‌شود.

### تفاوت معنای خروجی مبلغ در بانک‌ها

| بانک | کلید | معنای نمایشی |
|---|---|---|
| ملت | `output.Credit_Basket` | توان بازپرداخت، ریال |
| ملت | `output.Tavan_Baz_Pardakht` | سبد اعتباری به تفکیک رده |
| رسالت | `output.suggested_tavan_bazpardakht` | توان بازپرداخت پیشنهادی |
| پست‌بانک | `output.suggested_tavan_bazpardakht` | مبلغ وام پیشنهادی، ریال |

در توزیع مبلغ پست‌بانک، **۱۲۰ میلیون ریال** و **۳٬۰۰۰ میلیون ریال** ردیف‌های مستقل‌اند؛ بین آن‌ها بازه‌های بدون هم‌پوشانی قرار دارند. مقادیر خارج از محدوده زیر جدول اعلام می‌شوند، نه اینکه حذف یا به سقف تبدیل شوند. واحد داده تبدیل نمی‌شود.

در رسالت، شاخص **«توان بازپرداخت صفر»** همراه فهرست گزارش‌ها وجود دارد. فقط صفر ثبت‌شده شمرده می‌شود؛ null، خالی و غایب صفر نیستند.

### تسهیلات، تأخیر و سپرده

- مسیرهای هر بانک قطعی‌اند؛ از کلید مشابه یا مسیر جایگزین برای پرکردن دادهٔ غایب استفاده نمی‌شود.
- مسیرهای هر بانک قطعی‌اند؛ از کلید مشابه یا مسیر جایگزین برای پرکردن دادهٔ غایب استفاده نمی‌شود.
- در **هر سه بانک**، مقدار `TashilatItem` در مسیر قطعی همان بانک می‌تواند `null`، `[]`، یک آبجکت آیتم یا آرایه‌ای از آیتم‌ها باشد: **null صریح و آرایهٔ خالی بدون تسهیلات و شمار صفر**، **آبجکت غیرخالی یک تسهیلات** و **آرایهٔ سالم به تعداد اعضایش تسهیلات** محسوب می‌شوند. کلید غایب، آبجکت خالی `{}` و ساختار نامعتبر نامشخص‌اند، نه بدون تسهیلات. این قاعده در شمارش، جمع مبالغ، شاخص‌های رتبه‌بندی و هشدار تأییدشده یکسان است؛ دادهٔ خام بازنویسی نمی‌شود. شرط مبلغ معتبر، واحد پول و پیام تأییدکننده همچنان برقرار است. نام واقعی کلید با حروف بزرگ و کوچک **`TashilatItem`** است؛ مسیر جایگزین حدس زده نمی‌شود.
- تأخیر رسالت و پست‌بانک، بیشترین روز معتبر اقساط همان گزارش است. گروه‌ها `[30,60)`، `[60,90]` و `>90` هستند؛ هیچ گزارشی در دو گروه قرار نمی‌گیرد. روز نامعلوم صفر فرض نمی‌شود.
- ملت دو شاخص عددی قراردادیِ تعداد وام ثبت‌شده و میانگین اقساط قراردادی، و شاخص‌های مستقل پایش پوشش تاریخ پرداخت دارد؛ از اطلاعات ناقص پرداخت، تأخیر یا تسویه استنباط نمی‌شود.
- تعداد حساب سپرده با تعداد ماه‌های تاریخچه متفاوت است. تاریخ‌های ماه در جدول مستقل نمایش داده می‌شوند؛ ماه‌های تکراری در شمار ماه‌های یکتا یک‌بار شمرده می‌شوند.
- هشدار تأییدشدهٔ بدهی/چک نیازمند **گزارش موفق، پیام متناظر خروجی و دادهٔ ساختاریافتهٔ سمات** است؛ با آمار توصیفی تسهیلات تفاوت دارد.

### سپردهٔ حقیقی و حقوقی رسالت

طبق قاعدهٔ اعلام‌شده، بخش میانی `deposit_number` با `customer_code` مقایسه می‌شود: برابر = حقیقی؛ متفاوت = حقوقی. این برچسب، استعلام شخصیت حقوقی نیست. شماره باید سه بخش رقمیِ جداشده با نقطه داشته باشد؛ مقدار غایب، پوشانده‌شده یا نامعتبر «غیرقابل‌تشخیص» است. ارقام فارسی/عربی و صفرهای ابتدایی برای مقایسه یکسان می‌شوند؛ دادهٔ خام تغییر نمی‌کند.

- **دارای سپردهٔ حقوقی:** حداقل یک سپردهٔ حقوقی قابل‌تشخیص؛ همراه فهرست گزارش کامل.
- **فقط دارای سپردهٔ حقوقی:** تمام ردیف‌های سپرده حقوقی‌اند و ردیف حقیقی یا نامشخص وجود ندارد؛ همراه فهرست گزارش کامل. این گروه زیرمجموعهٔ گروه قبلی است.
- **تعداد سپرده‌های حقوقی در هر گزارش:** آمار فقط روی گزارش‌های دارای حداقل یک سپردهٔ حقوقی محاسبه می‌شود؛ گزارش‌های بدون حقوقی با صفر به مخرج اضافه نمی‌شوند.

فهرست‌ها تعداد حقیقی، حقوقی و نامشخص هر گزارش را نشان می‌دهند؛ شمارهٔ حساب و کد مشتری در جدول عمومی اضافه نمی‌شوند. نمودار حلقه‌ای بر پایهٔ **ردیف‌های سپرده** است، نه تعداد گزارش یا حساب یکتا؛ تکرار حساب در دو گزارش دوبار شمرده می‌شود.

### منابع اطلاعاتی مورد بررسی در رسالت

شاخص **«فاقد منابع اطلاعاتی مورد بررسی»** فقط وضعیت ورودی‌ها را نشان می‌دهد: تسهیلات صریحاً `null` یا `[]`، سابقهٔ وام `[]`، رتبه‌بندی فاقد داده با آستانهٔ **۳** و نبود سپردهٔ حقیقی با فهرست معلوم و بدون ردیف نامشخص. از این شاخص نام مدل یا مبلغ خروجی استنباط نمی‌شود.

### نمودارهای مکمل

- زیر کاشی‌های نمای کلی هر سه بانک، **توزیع تعداد تسهیلات سمات** در بازه‌های صفر، یک، دو تا سه، چهار تا پنج و شش یا بیشتر نمایش داده می‌شود. مخرج فقط گزارش‌های با شمار معلوم است.
- در بخش سپردهٔ رسالت، نمودار ترکیب ردیف‌های سپرده **بعد از کاشی‌ها** قرار دارد؛ جدول شمارنده‌های تکراری آن نمایش داده نمی‌شود.
- در بخش مدل‌ها، نمودار دایره‌ای سهم هر مدل فقط بر **گزارش‌های موفق دارای آبجکت خروجی و نام مدل رشته‌ای غیرخالی** محاسبه می‌شود؛ ناموفق‌ها و موارد بدون خروجی/نام مدل از مخرج کنار گذاشته می‌شوند. جدول و فهرست گزارش‌های هر مدل باقی‌اند.
- **کد وضعیت خروجی** در هر سه بانک نمودار حلقه‌ای دارد؛ همان دسته‌ها و قرارداد کد ثبت‌نشدهٔ جدول استفاده می‌شود.
- **ردهٔ امتیاز و بازهٔ امتیاز مدل رسالت** با نوارهای افقی مقایسه می‌شوند. طول نوار سهم واقعی از مخرج جدول است، نه نسبت به بزرگ‌ترین دسته؛ گروه ثبت‌نشده حذف نمی‌شود. ترتیب بر اساس فراوانی است، نه شدت ریسک.
- نمودار ستونی روزانهٔ موفق/ناموفق نیز در هر سه بانک باقی است. آمار عددی زمان اجرا و فهرست بیش از ۴ ثانیه تغییری نکرده‌اند.

با مکث روی قطعه یا راهنمای نمودار، قطعهٔ انتخابی برجسته و سایر قطعه‌ها کم‌رنگ می‌شوند. کادر راهنما نام شاخص، نام دسته یا تاریخ، ستون‌های تعداد/درصد و مبنای درصد را نشان می‌دهد؛ در نمودار روزانه، موفق و ناموفق دو ردیف جدا با مخرج کل همان روز دارند. انتخاب با صفحه‌کلید و لمس نیز ممکن است؛ Escape، لمس بیرون یا پیمایش کادر را می‌بندد. تنظیم کاهش حرکت سیستم رعایت می‌شود. نمودارها آفلاین و سازگار با حالت روشن/تیره و موبایل‌اند؛ جدول‌های مرتبط برای بررسی عددی باقی‌اند و دادهٔ خام تغییر نمی‌کند.

## 5. محرمانگی

**HTML عمومی به معنی بی‌نام یا غیرحساس بودن نیست.** هرچند JSON کامل گزارش‌ها داخل HTML نیست، شناسه‌های کامل پشت نمایش کوتاه، نام مدل، پیام‌ها و برخی مقدارهای هر گزارش در آن باقی می‌مانند.

- جمع بدهی/چک هر گزارش می‌تواند حساس باشد؛ برای گزارش تک‌موردی، جمع همان مبلغ مورد را افشا می‌کند.
- فایل همراهِ `reports/_ce-dashboard-private` دادهٔ کامل گزارش‌های منتخب را دارد. جدا بودن فایل‌ها، رمزنگاری یا احراز هویت نیست.
- متن پیام خروجی ممکن است خودش نام، مبلغ یا اطلاعات حساس داشته باشد؛ پیش از اشتراک HTML آن را بررسی کنید.
- کد ملی رسالت و پست‌بانک فقط در جزئیات خصوصی از `input.data.nationalCode` نمایش داده و با حفظ صفر ابتدایی کپی می‌شود. ملت کارت کد ملی ندارد.

| تغییرات نسخهٔ جدید دیده نمی‌شود | همهٔ فایل‌های `ce-dashboard` را به‌روزرسانی و HTML را دوباره تولید کنید؛ نسخه و مسیر اجرایی چاپ‌شده در ترمینال را ببینید. HTML قدیمی خودکار تغییر نمی‌کند. |
| پوشهٔ ورودی پیدا نمی‌شود | مسیر را نسبت به پوشهٔ اجرای فرمان بررسی کنید؛ در صورت نیاز مسیر کامل بدهید. |
| هیچ گزارشی تحلیل نشده | وجود فایل JSON و چیدمان `روز/success` یا `روز/fail` و مقدار `input.method` را بررسی کنید. |
| بانک اشتباه نمایش داده می‌شود | دادهٔ چند بانک را در یک ورودی گذاشته‌اید؛ بانک پرتعداد انتخاب می‌شود. ورودی‌ها را جدا کنید. |
| جزئیات باز نمی‌شود | HTML باید کنار `reports` تولید شده باشد و فایل همراه متناظر موجود باشد؛ اجازهٔ زبانهٔ جدید و مرورگر به‌روز را نیز بررسی کنید. |
| درصدها یا شمار گروه‌ها جمعاً کل را پوشش نمی‌دهند | برخی شاخص‌ها فقط دادهٔ معتبر دارند؛ null/غایب لزوماً «بدون سابقه/بدون حساب» نیست. تعریف مخرج همان بخش را بخوانید. |
| عددی نزدیک ۰٫۵ در ردیف دقیقاً ۰٫۵ نیست | تفکیک با مقدار خام است، نه عدد گرد‌شدهٔ میانگین یا نمایش. |
